# GiftPool — Agent Context

## What is this

GiftPool is a trustless group-gift escrow system on Solana. Friends pool SOL for a shared gift — if the target is met, funds go to the receiver; if the deadline passes without success, contributors can refund themselves. No trusted middleman.

Program ID: `88S4CSoaugjP3W6mFHq69vmHHa3J7xTaLrE21fzcCxDj`
Network: Solana Devnet

## On-Chain Architecture

### Accounts

| Account | PDA Seeds | Purpose |
|---------|-----------|---------|
| `PoolAccount` | `["pool", organizer, seed(u64 LE)]` | Pool state: organizer, receiver, name, target, total, deadline, status, bump |
| `ContributionAccount` | `["contribution", pool, contributor]` | Per-user contribution: amount, refunded flag, bump |
| `Vault` | `["vault", pool]` | SystemAccount holding pooled SOL. Program-sign only via invoke_signed |

### PoolAccount Fields

```rust
pub struct PoolAccount {
    pub organizer: Pubkey,        // Creator, can finalize
    pub receiver: Pubkey,         // Receives funds on finalize (defaults to organizer)
    pub seed: u64,                // Uniquifier for PDA derivation
    pub name: String,             // Max 50 chars
    pub target_amount: u64,       // Lamports needed
    pub total_contributed: u64,   // Running total (lamports)
    pub deadline: i64,            // Unix timestamp
    pub status: PoolStatus,       // Open | Succeeded | Refunding | Closed
    pub bump: u8,
}
```

### ContributionAccount Fields

```rust
pub struct ContributionAccount {
    pub pool: Pubkey,
    pub contributor: Pubkey,
    pub amount: u64,         // Total contributed (lamports), accumulates across multiple deposits
    pub refunded: bool,      // One-time refund flag
    pub bump: u8,
}
```

### State Machine

```
Open ──(finalize, total >= target)──> Closed
Open ──(first refund after deadline)──> Refunding
Refunding ──(all refunds claimed)──> Closed
```

### Instructions

1. **create_pool(seed, name, target_amount, deadline)**
   - Validates: name <= 50 chars, target > 0, deadline in future
   - Creates PoolAccount PDA + Vault PDA
   - Sets receiver = organizer by default

2. **contribute(amount)**
   - Constraints: pool must be Open, deadline not passed
   - CPI: system_program::transfer from contributor to vault
   - Creates ContributionAccount if needed (init_if_needed)
   - Accumulates amount in both pool.total_contributed and contribution.amount

3. **finalize_pool()**
   - Constraints: signer == organizer, pool Open, total >= target
   - invoke_signed: transfer all vault SOL to receiver
   - Sets status = Closed

4. **refund_contribution()**
   - Constraints: pool Open or Refunding, signer == contributor, not already refunded
   - Additional check: deadline passed OR target not met
   - Transitions pool Open → Refunding on first refund
   - invoke_signed: transfer contribution.amount from vault to contributor
   - Sets contribution.refunded = true, decrements pool.total_contributed

### Error Codes

| Code | Message |
|------|---------|
| NameTooLong | Pool name > 50 chars |
| TargetAmountZero | target == 0 |
| DeadlineInPast | deadline <= now |
| PoolNotOpen | Pool not in Open status |
| DeadlinePassed | Deadline passed (for contribute) |
| ContributionAmountZero | amount == 0 |
| MathOverflow | checked_add/sub overflow |
| Unauthorized | Wrong signer |
| TargetNotMet | total < target (for finalize) |
| PoolNotRefundable | Pool not Open/Refunding |
| AlreadyRefunded | Contributor already refunded |
| RefundNotYetAllowed | Deadline not passed AND target met |

## Web Frontend

### Design System

Dark theme with CSS custom properties. No CSS framework — all inline styles + CSS vars.

Key tokens:
- Background: `#09090c` (near-black)
- Surface: `#13131a` → `#1f1f2d` (elevated)
- Accent: `#ffffff` (white)
- Success: `#34d399` (green)
- Error: `#f87171` (red)
- Warning: `#fbbf24` (amber)
- Font: Inter (sans), JetBrains Mono (mono)
- Radii: 6px → 20px scale
- Easing: `cubic-bezier(0.16, 1, 0.3, 1)` (expo-out)

### Key Components

- **useProgram.ts** — Hook that creates Anchor Program instance from wallet adapter. Exports PDA derivation helpers (`derivePoolPda`, `deriveVaultPda`, `deriveContributionPda`) and unit converters (`solToLamports`, `lamportsToSol`).
- **PoolList** — Fetches all PoolAccount instances via `program.account.poolAccount.all()`, renders as cards.
- **PoolDetail** — Shows pool stats, progress bar, action buttons (contribute amounts, finalize, refund). Context-aware: shows different actions based on status, role (organizer vs contributor), and deadline.
- **PoolCreate** — Form: name, seed, target (SOL), deadline (hours). Derives PDA and submits create_pool tx.
- **Toast** — Custom toast notification system via ToastProvider context.

### Wallet Support

Phantom and Solflare via @solana/wallet-adapter. Auto-connect enabled. Devnet only.

## CLI Client

```bash
npx ts-node --transpile-only app/cli.ts create <seed> <name> <target_lamports> <deadline_unix>
npx ts-node --transpile-only app/cli.ts contribute <pool_pubkey> <amount_lamports>
npx ts-node --transpile-only app/cli.ts finalize <pool_pubkey> [receiver_pubkey]
npx ts-node --transpile-only app/cli.ts refund <pool_pubkey>
npx ts-node --transpile-only app/cli.ts info <pool_pubkey>
```

Uses keypair from `~/.config/solana/id.json`, connects to Devnet.

## Tests

Run: `anchor test`

Test scenarios:
1. **Happy path**: create pool → contribute 0.5 SOL → contribute 0.6 SOL (second wallet) → finalize → verify receiver balance = 1.1 SOL
2. **Refund path**: create pool (2s deadline) → contribute 0.3 SOL → wait 3s → refund → verify contributor balance restored

## Known Issues / Notes

- PoolDashboard.tsx appears to be an alternative/earlier version of the pool management UI (not used in current App.tsx routing).
- Web frontend uses inline styles extensively rather than CSS modules or styled-components.
- The `init_if_needed` Anchor feature is enabled for ContributionAccount — this is a security consideration (re-initialization attacks), though mitigated by the program logic.
